## Допущения и границы

- Fake Odoo — учебная модель, не доказательство версии/схемы клиента. Сервисы/конфигурации товара явно demo extensions.
- Только один учебный workspace; обе роли читают все его delivery records. Admin управляет crews/participants/skills/templates, operator — операционными действиями.
- Address, city и телефон требуются для нового planning. Unknown elevator отличается от no.
- Indoor/outdoor и area — буквальные классификации/фильтры; оптимизация маршрутов не реализуется.
- Fixed issue/photo type dictionaries — перечисления прототипа; task templates настраиваются.
- JSONB aggregate и глобальная transaction advisory lock выбраны для малого стенда; предел scan 5000.
- Нет real crew/customer authentication/product UI. Поступление результатов выполняется только явно локальным CLI/gateway через общие доменные правила, без публичного endpoint подмены автора.
- Подписи синтетические и маркированы DEMO; это не электронная подпись реального клиента.
- Нет real Odoo/customer connection, commercial order creation, Odoo writes, frontoffice, payments, routing, brokers, microservices или deployment.
- Файлы проверяются по имени, size, encoding и реальным image/PDF decoders, остаются attachment/nosniff. Это не антивирус и не production document sandbox.
- SQL/JSON/HTTP/config сначала unknown и runtime-validated; authored any, unsafe double assertions и подавления проверок не добавлены.
